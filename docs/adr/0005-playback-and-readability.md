# ADR 0005：乐谱合成播放、崩溃修复与可读性调整

- 状态：已采纳（2026-10-24）
- 依据：多代理调查。调查对象是用户的两首 YouTube 曲（Animenz 的钢琴改编：Avid、Call of Silence）；关键结论都经过独立验证

## 崩溃（已修复）

**原因**：卷帘的 `onScroll` 在延迟执行的 setState 里读取 `e.currentTarget`，而 React 19 在事件分发结束后已把它置为 null，于是抛出 TypeError。页面没有 ErrorBoundary，所以整棵组件树被卸载：页面变白，`<audio>` 元素也被移除，声音随之停止。

**触发**：播放时播放头到达右边缘，触发第一次自动滚动；在 1440 px 宽的窗口下，大约在 12–30 秒时发生。暂停时快速滚动 2–3 次也会触发。

**修复**：
- 先读出滚动值，再调用 setState。
- 每个面板单独包一个 ErrorBoundary，一个面板出错不会拖垮整个页面。
- 画布尺寸不变时不再重新分配。
- `pause()` 直接清除「正在播放」状态。原先依赖 `<audio>` 异步的 pause 事件；如果播放模式在事件到达前已切换，状态不会被清除，按钮会卡在「暂停」。

## 乐谱合成播放

- 在浏览器里用 smplr 的 SplendidGrandPiano 播放（MIT 许可，采样为公共领域）。用 Web Audio 提前 150 ms 排程；计时器跑在 Worker 里，标签页切到后台也不会被降频。
- 四种模式：原始录音、乐谱合成、叠加对照、左原音 / 右乐谱。合成可以跟随录音速度（经 `tempo_map` 换算），也可以按谱面匀速。
- 叠加模式下以录音为主时钟，实测漂移 ≤ 3 ms。暂停时的编辑，下次播放立即生效。
- 采样由 `/api/assets/piano/{name}` 提供：缺失的文件首次从上游下载并缓存到 `data/assets/piano/splendid`，之后可离线使用。
- 只加载乐谱用到的音高和中间力度层，缺失的音高用最近的键代替，避免一次解码全部采样（约 560 MB）。

## 可读性（量化 / 记谱）

| 改动 | 效果（用户两首曲） | 门限 |
|---|---|---|
| `repair_gaps` 惰性生成器 bug 修复 | 时间映射不再倒退（原先各有 13 / 15 处） | 新增单元测试 |
| 十六分六连音的复杂度 4 → 8 | Call of Silence 的三连音类拍数 114 → 26 | ASAP onset 中位数 0.932，平均 0.742（原 0.933 / 0.732） |
| 延音踏板覆盖的空隙按连奏处理 | 可见休止符每 100 音：22.6 → 2.5，22.1 → 4.3 | — |
| 第二声部的填充休止符隐藏 | — | 严格校验仍为 100% |
| 拍外的单个时值只要不跨小节中点，就不拆分 | 减少连音线 | — |

另外在 `provenance.versions.hands` 里记录实际用到的分手模型，并在检查器里显示。

## 未完成（见 evaluation.md 路线图）

还有一个问题没解决：节拍追踪会在曲中切换速度层级（倍速 / 半速）。例如 Call of Silence 被识别成 2/4、136 BPM，实际应为 4/4、68 BPM 左右。下一步计划：
- 用节拍激活值做速度连续性 DP。原型已显示，偏离网格超过 60 ms 的音符可从 10.2% 降到 0.4%。
- 在编辑器里加「速度 ×2 / ÷2」按钮。
- 建立真实音频评估集，用它作为回归门限。
