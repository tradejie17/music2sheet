# ADR 0006：用速度连续性 DP 统一节拍层级

- 状态：已采纳（2026-10-24；同日修订：小节相位修复、4 拍/2 拍阈值、复合拍速度记号，见做法 5、7–9 和「结果」）
- 代码：`quantize/beatdp.py`（新）、`pipeline/stages.py`（`s3_beats`）、`engines/beatthis_eng.py`
- 评估：`m2s eval-beats`（新），结果写入 `data/eval/beats/results.json`

## 问题

beat_this（不带 DBN）逐段挑峰值，曲中会在倍速 / 半速之间来回切换：

- Call of Silence 在 30 / 60 / 130 / 270 BPM 之间跳，相邻拍间隔变化超过 25% 的占 27.6%（原始峰值）；
- Avid 的前奏跟着 3+3+2 的重音分组走（约 95 BPM），后面约 143，中间几段掉到约 70，跳变占 31.4%。

`clean_beats` 只能补漏拍、删多拍，无法保证全曲同一层级；BPM 先验也只能整体折半或加倍，所以填了先验也不管用。

## 做法

1. **保存激活值**：beats 阶段除了原有的峰值结果，再把逐帧的 beat / downbeat logits 存成 `activations.npz`（50 fps，约 150 KB）。`STAGE_VERSIONS["beats"]` 改为 2，旧缓存会重新计算一次（约 5 秒）。`BeatGrid.activations` 记录这个文件的路径。
2. **全曲速度层级**（`track` → `_candidate_bpms` / `_score_level`）
   - **候选**：tracker 自身局部速度直方图的 3 个峰，加上激活值自相关的 2 个峰，再各取 ×½、×1、×2。
   - **打分**：每个候选先用下面的 DP 跟踪一遍，再按以下几项打分：
     - 拍点与激活峰的 F 值（精确率 × 召回率）；
     - downbeat 峰落在拍上的比例：3/4 曲子按半速跟踪时，小节线会落在两拍之间，这一项会把它压下去；
     - 层级混杂惩罚：局部速度偏离中位数超过 0.4 个八度的拍所占比例；
     - 两个对数正态先验，都在 ASAP 356 段演奏上实测得到：速度中位数 105 BPM，标准差 0.77 个八度；每拍节奏事件数中位数 3.56，下侧标准差 0.6 个八度，上侧 1.0 个八度。
   - **F 值的权重随 tracker 的可靠程度变化**：最佳 F ≥ 0.9 时权重为 8，tracker 自己的层级说了算；F ≤ 0.8 时权重为 2，此时 tracker 本身就在几个层级之间摇摆，交给先验决定。
   - **置信度**：最佳层级与「另一层级的最佳候选」之间的分差，换算到 0–1，记在 `provenance.versions.tempo_level_confidence`。
3. **DP 拍点跟踪**（`dp_track`，Ellis 式）
   - 奖励：beat 激活值 + 0.35 × downbeat 激活值 − 0.3。减去 0.3，是让落在空处的拍有代价。
   - 惩罚：相邻拍间隔变化 4·log²，偏离目标周期 1.5·log²。
   - 硬约束：拍间隔限制在目标周期的 0.6–1.67 倍以内，相邻两拍的间隔变化不超过 1.4 倍。
   - 这样允许渐变的速度变化和 rubato，但不允许倍速跳变。按块向量化计算，6 分钟的曲子每个候选约 15 ms，S3 全程约 0.1 秒。
4. **用户 BPM 先验**直接作为 DP 的目标速度，跳过层级选择。编辑器里的「速度 ×2 / ÷2」只要把 `priors.bpm` 设为当前值的 2 倍或一半，再调用 rerun 即可。当前速度可以从 `doc.tempos[0].bpm` 或 `provenance.versions.tempo_level_bpm` 读到。
5. **小节**：在新拍点上采样 downbeat 激活值，对 2、3、4 拍每小节的各个相位计算对比度，即小节位置的均值减去其他位置的均值。
   - 如果 downbeat 峰每 2 拍出现一次、强度一样，4 拍网格的对比度正好是 2 拍网格的 2/3。
   - 慢速 4/4 的半小节也常被标成 downbeat，但通常更弱，这会让比值高于 2/3。比值 ≥ 0.73（`FOUR_VS_TWO`）时选 4 拍。阈值的依据见「结果」：最初的 0.70 把 Chopin《摇篮曲》（6/8，比值 0.708）判成 12/8。
   - 输出的 downbeat 是规则的小节网格。`meter.py` 的逻辑不变，用户给了拍号先验时只挑相位。
   - **小节相位修复**（`repair_bar_phase`，3 拍和 4 拍时启用）：DP 偶尔会在延长记号或渐慢处多放一拍，或在紧缩处漏一拍，之后所有小节线都会错一拍。对每拍在小节中的位置做 Viterbi：正常情况下位置逐拍 +1；也允许「原地不动」（多了一拍，删掉 beat 激活较弱的那一拍）或「跳一格」（漏了一拍，在中点补一拍），每次代价 2.0（单位是 downbeat 显著度，约等于 4–5 个小节的清晰证据，`PHASE_REPAIR`）。每首曲子通常改动 0–4 处。
6. **慢速时自动细化网格**：DP 层级 < 80 BPM、速度稳定（相邻拍速度变化的中位数 < 0.05 个八度），并且网格是默认的 1/16 时，量化改用 1/32。原因是同一段音乐在 65 BPM 下需要三十二分音符；不细化的话，Call of Silence 每分钟有 33 个连音、9% 的音偏离网格超过 60 ms。rubato 很强的古典曲用 1/32 反而更碎，所以要求速度稳定。用户显式选的 1/8 或 1/32 不受影响。
7. **复合拍的速度记号**：`TempoMark.bpm` 一律按四分音符计。拍为附点四分（6/8、12/8）时 = 拍速 × 1.5，二分音符拍时 × 2。原来的公式把比例写反了（`× PPQ / bt`），附点四分拍的速度低了 2.25 倍：Call of Silence 按 ÷2 后谱面写成 ♩.=15，按谱面匀速播放和 MIDI 导出也慢 2.25 倍。`simplify.py` 里按秒算和声窗口的那一处原本也反着写，两处错误恰好抵消，已一并改正。
8. **慢速拍的单拍 / 复合拍判断**：比较单拍（÷8）与复合拍（÷12）的节奏拟合时，如果拍慢于 48 BPM（拍长 > 1.25 秒），÷8 的格子太粗，复合拍反而拟合得更好（Call of Silence ÷2 后变成 12/8）。这种情况下再在半拍网格上比较一次：半拍是单拍，整拍就是单拍。《摇篮曲》（♩.≈35）的八分音符落在半拍的三分位上，所以仍判为复合拍。
9. **编辑器**：结果低于 40 BPM 时「速度 ÷2」不可用，提示里写明原因：65 → 33 会把十六分音符变成六十四分音符。速度标签显示拍的单位（6/8 时为 ♩.）。用户填的 BPM 只是 DP 的目标，DP 会落到音乐上最接近的拍速（Avid 填 100 得到 142），这时 `provenance.versions.tempo_level_prior` 记下用户填的值，工具栏提示里会显示出来。
10. **兜底**：没有激活值时（旧缓存、合成测试、ASAP 合成评估）走原来的 `clean_beats` 路径，结果与改动前逐位一致。`provenance.versions.beats` 记录实际走的是 `dp` 还是 `legacy`。

## 结果

### 真实录音（`m2s eval-beats`）

数据：MAESTRO 音频中被 ASAP 标注了节拍的演奏，各取前 120 秒，指标用 mir_eval 计算，容差 70 ms。分三组：

- **调参集**：`m2s eval-beats` 默认的 18 段，覆盖 10 位作曲家，DP 的参数就是在这 18 段上调出来的。
- **留出集 A**：评审另选的 10 段，全部是 3 拍或复合拍（3/4、3/8、6/8）。
- **留出集 B**：修订时补的 27 段，以 2/4、4/4、2/2、12/8 为主，也有几段 6/8 和 3/4。

调参集上的数值都来自修订后的代码（`data/eval/beats/results.json`）：

| 指标 | 旧（峰值 + clean_beats） | **新（DP）** |
|---|---|---|
| Beat F | 0.866 | **0.880** |
| CMLt | 0.734 | **0.811** |
| AMLt（门限：不得变差） | 0.758 | **0.811** |
| 相邻间隔跳变 > 25% 的比例（标注本身为 0.149） | 0.165 | **0.046** |
| 跳变 > 1.6 倍的比例（不做相位修复时为 0） | 0.042 | **0.009** |
| 层级与标注一致的曲数 | 17/18 | **18/18** |
| 排版小节线的 downbeat F | 0.642 | **0.759** |
| 拍号与标注完全一致 | 9/18 | **13/18** |
| 下游：音高 + 位置都对的比例（Transkun → S3–S4，自动先验） | 0.726 | **0.736** |

- 改善最大的是旧方法层级来回跳的曲子：Glinka《云雀》AMLt 0.32 → 0.65，Chopin Op.10/10 0.64 → 0.87，Schumann Toccata 0.80 → 0.93。
- 变差最多的是 Rachmaninoff Op.23/4（AMLt 0.62 → 0.45）。这首 rubato 极强，局部速度在 30–66 BPM 之间变化，超出了 DP 允许的范围。

三组对比（downbeat F 指排版小节线的 downbeat F；「初版」是本 ADR 修订前的 DP）：

| | 调参集 18 段 | 留出集 A（10 段） | 留出集 B（27 段） |
|---|---|---|---|
| Beat F：旧 / 初版 / **修订后** | 0.866 / 0.880 / **0.880** | 0.907 / 0.902 / **0.900** | 0.881 / 0.853 / **0.851** |
| downbeat F：旧 / 初版 / **修订后** | 0.642 / 0.683 / **0.759** | 0.624 / 0.551 / **0.814** | 0.596 / 0.560 / **0.703** |
| 拍号完全一致：旧 / 初版 / **修订后** | 9 / 13 / **13** | 8 / 7 / **8** | 13 / 11 / **12** |
| 位置正确率：旧 / 初版 / **修订后** | 0.726 / 0.735 / **0.736** | 0.791 / 0.786 / **0.785** | 0.727 / 0.730 / **0.729** |
| 跳变 > 25%：旧 / **修订后** | 0.165 / **0.046** | 0.131 / **0.055** | 0.166 / **0.056** |

- 初版在留出集上的 downbeat F 低于旧方法：A 组 0.551 对 0.624，B 组 0.560 对 0.596。原 ADR 写的「downbeat 提升」只在调参集上成立。修订后三组都明显高于旧方法。
- 修订后的提升主要来自小节相位修复：Schubert D899/4 0.42 → 0.995（初版前 40 秒的小节线整体晚一拍），Moment Musical 1 0.44 → 0.80，Beethoven 12-1 0.54 → 0.99。
- 4 拍 / 2 拍阈值从 0.70 改为 0.73：
  - 《摇篮曲》从 12/8 回到 6/8，downbeat F 0.58 → 0.84，旧方法为 0.99；
  - Schubert D780/3、D935/3 回到 2 拍一小节。
- 留出集 B 上 DP 的 beat F 仍比旧方法低 0.03，原因是层级选择，不是跟踪本身：
  - Chopin 两首谐谑曲（标注为 ♩≈350，超出 `BPM_RANGE` 的上限 260）被 DP 跟在一小节一拍或两拍的层级上；
  - Beethoven 17-1（暴风雨）被跟在半速上。
  这几首的小节线反而更准。
- 4 拍对 2 拍的比值在 0.70–0.76 之间两类重叠，没有能把两类完全分开的阈值。仍判错的有：Appassionata（12/8，比值 0.718，判成 2 拍）和 Bach BWV 893（2/2，0.755，判成 4 拍）。
- 相位修复的代价：每处修复会留下一拍偏长（删拍）或两拍偏短（补拍）。拍间隔变化超过 1.6 倍的比例从 0 升到约 1%，8/18 段至少有一处。位置正确率没有变化。

| 层级置信度 | — | 0.24 | — | 0.22 |

| 小节数 | 200 | 98 | 374 | 94 |

- 两首都落在稳定的慢速层级上，节奏杂讯明显减少。
- 两首的层级置信度都很低（约 0.2）：tracker 在这两首里本来就各有约一半时间处在另一个层级。按 ×2 后得到 Avid 4/4 ♩=143、CoS 4/4 ♩=130，同样连贯。
- 「速度 ÷2」：修订前 CoS 65 → 33 得到 12/8、弱起 2 拍、谱面 ♩.=15。修订后 API 重跑 `{"bpm": 32.5}` 得到 4/4、♩=34、1/32 网格；编辑器里这个按钮已不可用，因为结果低于 40 BPM。Avid 按 ÷2 得到 4/4 ♩=36。
- 拍号先验 6/8：CoS 谱面写 ♩.=65，内部 `tempos[0].bpm` = 97.3，按谱面匀速播放和 MIDI 都按这个速度。
- 端到端验证：
  - 在隔离的数据目录里新建 Call of Silence 任务，完整跑一遍：beats v2 → DP → 4/4 ♩=65.2，用时 10.5 秒。
  - rerun `{"bpm": 130.4}` 后为 4/4 ♩=130.4，用时 6.4 秒；再改回自动，用时 4.6 秒。
  - 浏览器冒烟测试全部通过。
  - 修订后：在隔离数据目录中新建 CoS 副本任务（svsep 可用），e2e 的 toolbar、smoke、follow、playback 全部通过。toolbar 的 ×2 → ÷2 回到原层级，并检查 65 BPM 时 ÷2 不可用；latency 中位数 1.46 秒，含 0.6 秒防抖。

## 局限与后续

- 层级本身有歧义（倍速 / 半速），先验只能给出更可能的一种。界面应显示置信度，并提供「速度 ×2 / ÷2」按钮，由前端实现。
- 只用一个全曲层级。真正变速的曲子（慢引子接快板）需要分段先验，见路线图第 4 项。
- 4 拍对 2 拍只依据 downbeat 强弱交替来判断，比值在 0.70–0.76 之间两类重叠，靠阈值无法完全分开。没有交替时按 2 拍处理，用户可以用拍号先验纠正。按小节时长加先验（4 拍小节 > 4.5 秒时少选 4）在现有数据上能多对一首（Liszt TE 3），但样本太少，没有采用。
- 相位修复只处理 3 拍和 4 拍：2 拍时「多一拍」和「少一拍」无法区分。每次修复会留下一个不规则的拍。设 `PHASE_REPAIR = None` 可以关掉。
- 很短的片段（DP 找到的拍少于 8 个，约 8 秒）仍然退回旧方法，工具栏不显示层级和 ×2/÷2 的依据。
- 拍速 > 80 BPM 时不会自动切到 1/32 网格。按 ×2 后三连音拟合会多出很多连音：Avid ♩=143、简化 1 级时有 84 个连音标记，♩=71 时只有 8 个。所以 ×2 只是给层级判断错时用的出口，不是推荐的读法。
- 两首用户曲的层级置信度只有约 0.2，选慢层级还是快层级接近抛硬币，对每拍事件数先验的中心值很敏感。
- 第 6 条只调整默认网格。用户无法区分「默认的 1/16」和「我明确选了 1/16」，以后可以给 `Priors.min_grid` 加一个 `auto` 选项。
- 参数在 18 段演奏和 2 首用户曲上调出，存在过拟合风险。最敏感的是每拍事件数的中心值：改成 3.2 时，两首用户曲都会翻到快层级。评估集扩大后需要重新校准。
