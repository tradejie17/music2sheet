# ADR 0007：乐谱简化级别（原样 / 易读 / 简化）

- 状态：已采纳（2026-10-24）
- 代码：`notation/simplify.py`（新）、`models/priors.py`（`Priors.simplify`）、`models/scoredoc.py`（`Engraving`）、`pipeline/stages.py`（S6 调用）、`quantize/quantizer.py`（`requantize`）、`notation/build_m21.py`（8va、整拍时值合并、三连音省略括号、开头谱号）、`pipeline/rederive.py`、`api/app.py`、`cli.py`
- 前端：`Toolbar.tsx`（「简化」下拉框、「速度 ×2 / ÷2」）、`PriorsForm.tsx`（「乐谱简化」）、`api/types.ts`

- 评估数据：`data/eval/simplify/`（`metrics.json`、`png/`、生成脚本 `scripts/`）

## 问题

用户要求乐谱「人能读」：节奏连贯、前后一致，没有无关的符号，并且可以选择把生成的乐谱简化。

节拍层级统一（ADR 0006）之后，忠实转录仍然很难读，因为它把演奏里的一切都写了出来：

- 装饰音和回音被量化成三十二分音符或连音；
- 和弦里有重复的八度音；
- 手指提前松开，变成休止符或更短的时值；
- 一个音在其他音之上延续，就多出第二声部；
- 每次换踏板都标一次 Ped. / *。

两首用户曲（Animenz 改编）在原样级别下：每 100 个音有 11–20 条连音线；17–33% 的小节有两个声部；每小节 38–43 个符号。

## 决定

`Priors.simplify` 有三个级别。它属于先验参数，所以「简化」下拉框、「重新生成…」对话框和 CLI `--simplify` 走的都是 rerun：用缓存的转录和节拍重算 S3–S6，几秒钟完成。

| 级别 | 名称 | 内容 |
|---|---|---|
| 0 | 原样 | 照写转录结果，与引入本选项前逐位一致 |
| 1 | 易读 | 保留所有旋律与和声音，只改写法 |
| 2 | 简化 | 改编：右手旋律 + 左手柱式和弦 |

简化在 S5（分手、声部）之后、S6 结束前对 ScoreDoc 原地改写（`simplify(doc, level, onset_s, grid_level, offset_s)`）。重新量化用的是**演奏时间**，不是原样乐谱的网格：S4 把每个转录音的 onset / offset 存进 `Ctx.perf_s`。

用户锁定的音不会被删除，也不会被移动。

### 级别 1（易读）

1. **装饰音**（`_drop_ornaments`），满足以下任一条件就删除：
   - 1–3 个单音，彼此间隔不到 90 ms，与后面的主音相差 1–3 个半音，且主音前后各空出 200 ms；
   - 一个短于 80 ms 的音，100 ms 内紧跟一个相差 1–2 个半音、至少两倍长的音。即使两者已被量化成同一个和弦，也会删除。
2. **和弦精简**（`_reduce_chords`）：
   - 保留最高音（旋律）和最低音（低音）；
   - 内声部中，删除重复已有音级的音（右手旋律下方的八度除外），删除比周围最响的音轻 45% 以上的短音；
   - 每只手每个和弦最多 4 个音。
3. **重新量化**（`_resnap` → `quantizer.requantize`）：
   - 网格不变，用原来的细分 Viterbi；
   - 不允许六连音；三连音的复杂度 × 1.6，只有整拍明显是三分时才用；
   - 最细一级细分的复杂度从 2.5 提高到 6，只有真正的快速音群才用它，单个偏差的 onset 不会被拉到最细网格；
   - 同一只手 70 ms 内的 onset 合并成一个和弦；
   - 重新量化后再精简一次和弦，因为网格可能把相邻的 onset 并到一起。
4. **每行谱表一个声部**（`_single_voice`）：
   - 同时开始的音合成一个和弦，共用一个时值；
   - 下一个和弦的距离在半拍以内或在踏板下时，和弦一直延续到下一个和弦；否则结尾取「音符 + 后面的休止符」写出来最省符号的位置（`_nice_end`）；
   - 新规则（`_rest_reads_better`）：一个多音和弦已经停在可以单独写出的时值上时，如果延续到下一个和弦需要在每个音上加连音线，就改为写一个休止符。休止符只是一个符号，而连音线会让每个音都多一个符头和一条弧线。单音照旧延续，因为一条连音线和一个休止符的代价相同。
5. **记谱**（`ScoreDoc.engraving`，只影响谱面，不影响声音）：
   - `pedal_marks=False`：踏板只在开头标一次「con Ped.」。踏板仍保留在 doc 里，播放和 MIDI 不变。
   - `ottava=True`：音域很高的段落加 8va，很低的段落加 8vb（`build_m21.ottava_spans`，第二轮修订）：
     - 种子：连续 ≥ 6 个起音都在 G5 以上（或 F2 以下），其中有音到 E6（或 A#1）；或单个音需要 ≥ 5 条加线（B6 及以上 / D1 及以下）。只需 4 条加线的单音（G6、A6）照旧写加线。
     - 扩展：括号向两边延伸到乐句边缘（遇到休止符或小节线停止），只纳入移八度后仍好读的音（8va：≥ C5；8vb：≤ C3）。
     - 合并：两段括号相隔不到一小节、中间的音也都好读时合为一段。
     - 防假跳进：边缘拍里有未加括号、却比括号内的音更高（8va）/更低（8vb）的相邻音时，把这一拍剔出括号。
     - 括号短于一拍不加；不足 6 个起音的短括号如果两小节内又出现另一个短括号（来回开关），两段都不加。
     - 效果（cos / avid）：括号数 L1 54 → 10、27 → 3；L2 41 → 7、21 → 4；同一小节开关两次的情况为 0。
   - `tidy=True`：
     - 从拍点开始的长音按整拍合并，例如 3½ 拍写成 3 + ½，而不是 1 + 1 + 1½；
     - 与前一组节奏相同的三连音组不再印括号和「3」。
6. **自动换谱号**（`_auto_clefs`，第二轮修订）：每个谱表在「本谱号 / 另一谱号」两个状态之间**按拍**做 Viterbi。
   - 代价是该拍各音在这个谱号下的加线代价 `_ledger_cost(l) = l² + 15·max(0, l−3)`：超线性，少数极远的音比许多稍高的音更重；
   - 加线数在 8va / 8vb 移位**之后**计算（先定 ottava，再定谱号）；
   - 每在另一谱号停留一小节加 1，每换一次谱号加 12，在小节中间（拍点上）换再加 8；
   - 效果：cos L1 第 25 小节左手在低音 G2/F#2 之后才换到高音谱号；第 48–51 小节的 A2–A4 琶音留在低音谱号；avid L1 第 29 小节（C3/D3）留在低音谱号。
   - 旧做法（第一轮）按小节线性求和加线，几个很低的音会被许多稍高的音压过，低音被写在高音谱号下 4–6 条加线处。

### 级别 2（简化）

> 第二轮修订：级别 2 的网格改为绝对下限——最细网格单位 ≥ 0.28 s（`Profile.min_unit_s`，`_floor_level`），♩ ≤ 107 时即八分音符，而不是「比 min_grid 粗一级」（两首用户曲目 min_grid 都是 1/32，旧做法只粗到 1/16）。右手同一网格点上落了多个演奏 onset 时，按天际线保留最高音所在的 onset（旋律在分解和弦的顶部），左手仍取离网格点最近的。结果：右手不在八分网格上的 onset，cos 40% → 0%，avid 36% → 0%。

级别 1 的全部步骤，另外：

- **右手**：旋律（最高音）加最多一个和声音（最响的那个，八度重复的不算）。
- **网格粗一级**：例如 1/16 → 1/8，并且不用连音。
  - 同一只手两个不同的演奏 onset 落到同一个格点时，只保留离格点最近的那组音（`_one_onset_per_tick`），不把快速音群里相邻的旋律音叠成音簇。
  - 一个音提前一个网格单位、并延续过下一拍（流行乐的切分「抢拍」）时，改为从拍上开始（`_straighten`）。
- **复合拍**：离拍 onset 有一半以上落在三连音位置时（连续的三连音音型），2/4、3/4、4/4 改写成 6/8、9/8、12/8（`_to_compound`）。这样三连音就写成普通的八分音符，听起来不变。改写记录在 `provenance.versions.simplify_meter`。
- **左手柱式和弦**（`_lh_blocks`）：
  - 和声窗口取小节的约数，长度约 1.8 秒；
  - 每个窗口一个和弦：最低音，加上时值 × 力度最大的两个其他音级，排在低音上方 16 个半音以内；只有八度交替时保留八度；
  - 和弦从窗口内第一个 onset 所在或之前的拍开始；
  - （新）和弦时值取能单独写出的最长时值。例如 9/8 小节里写附点二分音符，后面接休止符，而不是附点二分连附点四分。
  - 右手休息的窗口，左手保持原样。

### 其他修改

- **原样级别逐位不变**：`simplify(doc, 0)` 直接返回；`Engraving` 的默认值等于旧行为；`requantize` 是新函数，`quantize()` 本身没有改动；8va、整拍合并、三连音省略括号都由 `engraving` 开关控制。
- **重新分手 / 重新分声部**（`rederive`）：在级别 1 或 2 的 doc 上执行时，结束后再调用 `one_voice_per_staff`，保证仍然是一行一个声部（新）。
- **默认级别**：
  - 新任务默认级别 1。网页上传、CLI 和 `POST /api/jobs` 都一样：API 没传 `simplify` 时设为 `NEW_JOB_SIMPLIFY = 1`。
  - `Priors` 模型的默认值仍是 0，因为数据库里旧任务的 params 没有这个字段，它们按原样级别生成。前端读到缺失值时也当作 0。
- **工具栏**：
  - 「简化」下拉框和「速度 ×2 / ÷2」都改 job 的 params 再 rerun，并保留其他先验参数。
  - doc 编辑过时（`provenance.versions.edited` 或有撤销历史），rerun 前会先确认；手动修改留在历史版本里。

## 为什么新任务默认用级别 1

- **级别 1 不丢音乐**：
  - 五首曲子保留了 98.4–99.8% 的音；
  - 旋律保留率（原样乐谱每个右手 onset 的最高音，是否仍以同一个源音、同一音高留在谱里）≥ 0.99；
  - 与录音的色度相似度变化不超过 ±0.006；
  - MusicXML 全部通过严格校验。
- **级别 1 明显更好读**：
  - 第二声部从 4.5–33% 的小节降到 0；
  - 用户两首曲每 100 个音的连音线从 11.3 / 19.7 降到 8.8 / 14.5；
  - 每个音平均的符号数下降 8–19%；
  - Haydn 的连音从每分钟 13.5 个降到 0.5 个，休止符减半；Schubert 的连音从每分钟 95.5 个降到 31 个，余下的大多不印括号。
- **级别 2 是改编，不适合当默认**：
  - 会删掉 14–54% 的音，旋律保留率 0.59–0.94；
  - Haydn 的十六分音阶在八分网格上会丢掉一半；
  - 适合视奏或初学，所以作为选项提供。
- **级别 0 仍可一键切换**：校对转录、导出 MIDI（量化）或做研究时用。

## 结果

测试曲目：
- 用户的两首曲：Call of Silence（cos）、Avid。使用缓存的转录、beat_this 激活值和 piano_svsep 分手；没有写入用户任务的目录。
- 三段 MAESTRO 录音：Haydn、Schubert（Impromptu，3/4 三连音）、Bach（2/4）。

指标说明：
- 「符号/音」：MusicXML 中可见的符头、休止符、连音线、连音标记、附点、临时记号、踏板、8va、文字、谱号之和，除以音数；
- 「节奏型/10 小节」：每 10 小节内不同的「小节内 onset 位置集合」个数，两个谱表取平均；
- 「旋律」：见上一节；
- 「色度」：谱面（含踏板延音）与录音的色度余弦相似度。

## 验证

- **原样级别逐位不变**：
  - 用当前代码重算 Call of Silence（同一份缓存的转录和节拍激活值，piano_svsep 分手），与引入简化前的流水线产出（`m2s serve` 生成的 `doc_rev_0`，2026-10-24 16:07）比较：音符完全相同，MusicXML 只有随机生成的 part id 不同。
  - ASAP 回归门限只跑原样级别，`pytest -m slow tests/regression` 7 项全部通过，门限未改动。
- **单元测试**（`test_simplify.py`，10 项）：
  - 合成演奏上，级别 0 等于默认结果；
  - 级别 1：一行一个声部，旋律召回 ≥ 0.95，装饰音被删，每个和弦 ≤ 4 个音，踏板只印一次，MusicXML 通过校验；
  - 级别 2：右手和弦 ≤ 2 个音，左手 onset 数至少减半，低音保持在底部，没有连音；
  - 锁定的音被保留；
  - 整拍合并；
  - 8va 和三连音省略括号；
  - 单独的极高音加 8va；
  - 谱号 Viterbi；
  - 休止符优先于和弦连音线；
  - 级别 1 的 doc 重新分手 / 分声部后仍然是一个声部。
- **API 测试**：
  - rerun 接受 `simplify`，拒绝 3；
  - 新任务默认 1，显式传 0 时保留 0。
- **浏览器测试**（`tests/e2e/toolbar.py`，全部通过）：
  - 环境：独立数据目录、带 worker 的 `m2s serve --port 8401`，对 Call of Silence 的副本任务运行。
  - 简化 1 → 2 → 0：每次约 6 秒加载新版本。级别 2 一行一个声部，右手 ≤ 2 个音，音数 1448 < 2491；级别 0 有 2523 个音，踏板全部印出。
  - 「重新生成…」对话框：设回 1 后得到同一份乐谱。
  - 速度 ×2：拍速 65.2 → 130.4，`tempos[0].bpm` 也翻倍，小节数 93 → 183，仍是 4/4，简化级别不变。
  - 速度 ÷2：回到 65.2 和 93 小节。
  - 编辑过的 doc：rerun 前弹出确认框。
  - 没有页面错误。
  - `smoke.py` 也通过。

## 局限与后续

- 级别 2 在快速经过句上丢音较多：Haydn 只保留 46% 的音，旋律 0.59。可以考虑按段落自适应网格：慢的段落用原网格，快速音阶保留首尾和拍上的音。
- 复合拍改写只对全曲生效。曲中只有部分段落是三连音时，级别 2 会把其余三连音删并到二分网格上。
- 左手柱式和弦的音级按「时值 × 力度」挑选，没有做和声分析。转位和七和弦可能被写成三和弦。
- 级别 1 的左手仍然照写演奏节奏。例如 Avid 左手的三三二分组，仍有较多十六分音符和附点。
- 简化是 S6 内的一次性改写。在简化后的 doc 上手动编辑之后，再切换级别会从头生成，手动修改只留在历史版本里。
